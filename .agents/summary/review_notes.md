# Review Notes

## Consistency check

- Entry point names in `package.json` exports match `src/entries/` and the
  `src/platform/adapters/` hosts (opencode, opencode2, pi, dsh, codex) — consistent
  across README, `docs/project-structure.md`, and this documentation.
- Built-in default functions `[plan, execute, loop]` are stated consistently in
  `docs/role-yaml.md` and `docs/functions.md`-derived material.
- Memory defaults (`inject: true`, `max_inject: 10`, `min_relevance: medium`,
  `scope: both`) agree across `docs/role-yaml.md` and `docs/memory.md`.
- Dispatch defaults (`budgetSampleIntervalMs: 30000`,
  `backgroundStaleTimeoutMs: 900000`, `syncPromptTimeoutMs: 600000`) are stated
  only in `docs/role-yaml.md`; they were not cross-checked against
  `src/dispatch/config.ts` in this pass.
- Host version policy (channels, `check:hosts`, daily workflow) is consistent
  between AGENTS.md, `scripts/host-versions.ts`, and README badges.

## Completeness gaps

- **Large module surface**: `src/` has ~727 TypeScript files across 35 top-level
  modules. This summary documents each module's responsibility at directory
  level; per-file detail (e.g. inside `src/graph/` subpackages such as
  `contracts`, `policy`, `persistence`) is available in the dedicated docs
  (`docs/graph-engine-architecture.md`, `docs/graph-outcome-protocol.md`,
  `docs/graph-v3-operations.md`) and is not duplicated here.
- **Codex adapter**: less documented than the other hosts; `docs/codex.md` exists
  but the internal structure (`mcp/`, `app-server/`, `installation/`, `desktop/`)
  was summarized from directory layout only.
- **TUI internals** (`src/tui/`) and the dsh web client (`src/platform/adapters/dsh/web/`)
  were not deeply analyzed; only their build scripts and frameworks are documented.
- **Language support**: single-language (TypeScript) codebase; no
  language-support limitations apply to this analysis.
- **Benchmark infrastructure** (`src/benchmark/`, `docs/benchmarks.md`,
  `docs/benchmark-infrastructure-design.md`) was catalogued but not detailed.
- The exact v3 graph declaration schema (fields of a declaration) lives in
  `docs/graph-v3-operations.md` and was not reproduced in `data_models.md`.

## Recommendations

1. For deep graph work, read `docs/graph-engine-architecture.md` and
   `docs/graph-outcome-protocol.md` directly; this summary intentionally stays at
   the pipeline level.
2. Before changing user-facing configuration behavior, consult
   `skills/rolebox-config/references/*.md` (the shipped agent guide) — the
   repository requires updating it in the same change.
3. `AGENTS.md` (repo root) is the authoritative agent-behavior file; the
   consolidated file generated by this run defers to its hand-maintained
   conventions in the Custom Instructions section.
